# TreeDebater 与 streaming 代码重组计划

本次重组让 TreeDebater 持续拥有辩论能力，让 streaming 负责渐进发言及并发调度。保留首段优先、正文持续补写修复、紧凑观众反馈、提前修订和音频复用。通过共享能力、明确参数和输入快照实现提速，保留原接口及普通调用的默认行为。

状态：已完成代码重组与本次范围的离线验收。真实模型的延迟和质量尚未重新测量；本轮没有启动付费实验。下列原计划保留为职责和兼容契约，实施结果见本节。

## 目标与边界

- 保留 `opening_generation`、`rebuttal_generation`、`closing_generation`、`speak`、`listen` 及原有选论点、检索、反馈、修订接口。
- 普通整篇生成、首段与正文联合预写、正文更新、提前修订使用共同的辩论规则与能力实现。
- streaming 可以决定何时生成、生成哪部分、采用哪种反馈长度及如何复用结果；具体的论点选择、检索和证据策略由 TreeDebater 提供。
- 继续支持 `full_script`、`overlap_prefix`、`listening_prefix`、`incremental`；CLI、应用适配器和实验入口共享阶段时长与配置解释。
- 本次不更换模型、不调整评价标准、不重做辩论树算法；确需改变策略的部分使用显式选项，并单独验证。
- 先保持已有行为和优化，再消除重复实现；不以一次性搬动大量文件作为完成标准。

## 原接口如何扩展

保留现有必填参数、返回形状及默认行为。新能力优先使用可选关键字参数；下列名称描述职责，最终命名随现有代码风格确定。

| 原接口 | 保留职责 | 新增支持 |
| --- | --- | --- |
| `claim_selection(history)` | 原主论点选择与框架建立 | 显式选择原策略或保存分数策略；可缓存准备结果，输入变化时检查有效性 |
| `_prepare_stage_prompt(history, max_time, **kwargs)` | 阶段材料与提示入口 | 接收准备好的快照、任务范围、旧草稿、固定文本和输出格式，避免重复选论点或检索 |
| `_get_response(messages, **kwargs)` | 原模型执行扩展入口 | 与后台快照执行共享底层执行器、模型参数、重试和计费；验证实例或子类扩展仍有效 |
| `_get_feedback_from_audience(statement, history, **kwargs)` | 原观众评价与检索反馈 | `full` 或 `compact` 输出；固定首段与可编辑范围；隔离观众会话 |
| `_select_revision_evidence(...)` | 原补充证据选择 | 继续支持不可变候选池，提前结果与最终选择使用同一实现 |
| `_get_revision_suggestion(...)` | 组合反馈、证据选择及原记录语义 | 消费已验证的提前结果，不再发起相同请求；后台执行与状态提交分开 |
| `_length_adjust(...)` | 原修订与长度控制入口 | 共用修订提示；支持固定文本、剩余预算、提前修订结果和明确的长度适配策略 |
| 三阶段 generation 接口 | 阶段生命周期、交付与树更新 | 选择整篇或渐进编排，不改变辩论能力来源 |

不能让后台线程直接调用会修改当前 player 的旧方法。先将方法内的“准备输入、构建提示、执行请求、提交状态”分离，普通调用和后台调用共享中间能力。自定义模型执行入口必须可注入并被两条路径使用；若某个旧扩展依赖可变状态，保留其串行执行路径并禁用对应推测任务，不能静默绕过。

## 快照与操作约定

优先扩展现有快照和 `BodyTask`，不另建通用工作流框架。每个请求携带其实际需要的数据：

- 回合、阶段、立场、输入版本、当前 ASR 文本及是否完整；保留真实发言的角色归属。
- 我方定义和已选论点、双方树的相关结构与交锋状态、战场和动作材料、检索结果、证据候选池。
- 已播放文本、为当前交接冻结的文本、尚可修改的草稿，以及草稿版本。
- 当前任务范围、阶段总时长、剩余时长及统一草稿长度预算。
- 观众配置、提示模式、模型与采样参数，以及使用的选择和修订策略。

生成操作区分整篇生成、首段与正文联合预写、正文更新、正文反馈修订。首段优先是交付与调度能力，不强制增加一个独立模型请求：当前“一次写出首段和初稿、先审查交付首段”的方式继续保留；以后如增加只写首段模式，作为独立选项验证。

正文更新输入包括最新材料和旧草稿，输出完整的新版未播放正文。允许补充、删除失效论证、修复归属和调整段落衔接，不限定为尾部追加。初期继续沿用完整正文输出，不引入文本补丁协议。

## prompt 共用方案

一个请求由共享辩论规则、共享材料、所选操作约束和唯一输出格式组成。普通路径默认采用原完整格式，streaming 选择需要的任务格式。

| 提示内容 | 共用定义 | 按任务选择的内容 |
| --- | --- | --- |
| 系统角色与修辞风格 | 现有 debater 系统提示及实例覆盖 | 使用实际配置的模型、温度和 token 上限 |
| opening、rebuttal、closing 策略 | 三阶段现有策略块 | 适用于整篇、首段或剩余正文的结构约束 |
| 材料和历史 | 定义、论点、双方树、检索、证据、角色正确的发言历史 | 完整或部分输入、当前相关材料、旧草稿与新增输入 |
| 修订规则 | 事实与归属、原有修订政策、最小修改、证据支持与口头来源 | 整篇或正文可编辑范围、首段冻结、剩余预算 |
| 观众评价 | 原四个评价维度、阶段注意事项、启用的检索反馈 | 完整分析或紧凑问题列表 |
| 输出格式 | 集中维护格式定义和解析约定 | 原 Plan 与 Statement、首段与正文 JSON、正文 JSON 或纯发言 |
| 首段可发布审查 | 共用事实材料和来源表达 | 保留独立的立场、提前可说性、新输入冲突检查及审查格式 |

具体处理：

1. 保留三阶段完整模板导出，让旧调用仍得到原模板；从同一规则块组合 streaming 任务。
2. 从 `post_process_prompt` 明确拆出修订规则、证据规则、结构要求和输出要求。正文任务不包含“缺少概述就增加概述”，整篇任务仍可包含。
3. 从 `audience_feedback_prompt` 明确拆出评价规则、材料和输出格式，替代通过 `split` 截取整段字符串的办法。
4. 统一材料构建，避免普通路径有双方树和检索反馈、streaming 路径却遗漏。对大树使用已有选择和上下文预算，保留所选节点的必要祖先、交锋关系、归属与状态，不无条件展开全部树。
5. 准备材料、推测战术和旧草稿明确标为内部材料，不混入对手发言或已证实证据。
6. 整篇和正文不必共享完全相同的最终字符串；测试应验证共同规则、有效材料和唯一输出约束，而非要求所有提示字节相同。

## 保留的提速机制

| 机制 | 实现要求 | 正确性边界 |
| --- | --- | --- |
| 紧凑反馈 | 同一观众反馈构建函数选择 `compact`；保留最多三项关键问题、最多 180 英文词的当前优化 | 评价维度及启用的检索不被关闭；有问题时不能因格式压缩误返回 No changes |
| 首段先交付 | 首段审核和预合成可先完成；正文继续工作 | 首段发布时间受最新输入审查约束 |
| 正文增量更新 | 保留当前新增词数门槛、待处理输入合并和转写更正触发 | 更正、撤回或首段改变不能被普通词数门槛阻塞 |
| 提前反馈与修订 | 完整 ASR 到齐后，可与最终树分析并行 | 采用相同观众配置、提示规则和证据选择；使用隔离快照 |
| 补充证据 | 提前选择结果传入提前修订 | 即使反馈为 No changes 且长度合适，选中补充证据仍触发修订 |
| 结果复用 | 校验实际输入依赖后复用选择、反馈、修订和音频 | 真实历史、草稿、模型选项或相关证据变化时，旧结果失效 |
| 单次主体修订 | 保留现有显式开关 | 后续 TTS 长度适配不能改写立场、证据归属或已交付文本 |
| 检索缓存 | 保留目标、版本、阶段等现有缓存依据 | 不能由于选择了快反馈就静默忽略检索配置 |

`compact` 只控制观众输出；内容更新频率、检索策略、修订次数和并发开关各自独立。普通原调用保持完整反馈默认值；现有听时预设显式选择紧凑模式。

保存分数选论点、局部检索等已有优化同样保留为明确策略。普通 `claim_selection` 默认使用原策略；需要维持现有实验行为的预设显式选择保存分数策略，不能由 `speech_mode` 隐式切换。迁移前保存解析后的配置，逐项核对新旧含义。

## 渐进发言生命周期

1. **准备与听取**：原能力完成论点和证据准备，按序处理对手输入、更新树并产出快照。
2. **首段准备**：streaming 调用共同生成能力得到首段及初稿，执行专用首段审查，准备可复用音频。
3. **正文持续更新**：普通细节更新主要修改正文；实质性范围或立场变化触发首段重新审查。未发布首段可以在受控条件下更换，并使旧音频失效。
4. **交接与冻结**：选定首段、绑定输入和版本，检查是否可交付。为交接冻结和实际已播放是两个状态；已经播放的文本始终不可改写。
5. **完整输入协调**：ASR 完整后提前反馈、选择证据和修订，与最终树分析并行；最终状态拥有者验证可复用性。若新输入推翻已播放首段，只能在未播放正文明确澄清，不能回写已播放记录。
6. **正文交付**：选择有效草稿或修订结果，复用匹配音频，按真实首段音频时长计算剩余预算，并将交付边界推进到后续正文块。
7. **提交与收尾**：记录实际交付的文本与树更新；失败时保留已播放部分。取消或重录使旧回合任务失效，迟到结果不得进入新回合。

缓存匹配以实际请求依赖为准。仅排序或展示方式改变不应导致重复请求；相关树内容、历史角色、反馈策略或提示版本实际改变时必须失效。保留最终派生树信息变化时的明确匹配规则，不能用全对象相等无差别阻塞复用，也不能忽略已进入提示的有效变化。

`used_evidence` 保持原“已选择或消费”的约定，不在此次重构中暗改为“实际已朗读引用”。推测选择不写该集合；被回合接受的选择按原提交语义记录一次。实际播放记录单独保留。

## 分阶段实施与验收

| 阶段 | 工作 | 验收与退出条件 |
| --- | --- | --- |
| P0 基线与契约 | 冻结当前源码和解析后的配置；整理原接口、调用次数、请求材料和已有测试 | 区分原接口兼容测试与现有模式行为测试；复现检索反馈丢失和生成扩展被绕过 |
| P1 共用 prompt | 提取评价、修订、材料和格式组合；保留原模板 | 原普通模板保持一致；三阶段共用策略；无双重输出要求或重复开头指令 |
| P2 共用执行能力 | 分离准备、执行、提交；连接原生成、观众和修订扩展点 | 自定义执行器和模型参数对普通及推测路径均生效；成本和请求数准确；无后台状态写入 |
| P3 接回原业务配置 | 恢复检索反馈，选论点策略显式化，保持原检索与证据入口 | 相同能力配置得到相同有效材料；快速模式仍包含启用的检索；关闭功能确实不调用 |
| P4 接入首段与正文更新 | streaming 使用共同提示和执行能力，保留审查、预合成、增量更新 | 首段可先交付；新输入持续修复正文；更正输入触发更新；阶段预算及首段扣除正确 |
| P5 提前反馈修订与交接 | 紧凑反馈、补充证据、提前修订与最终复用统一 | 同输入只执行一次反馈、选择和修订；变化输入不复用旧结果；首段播放不等待最终树分析 |
| P6 音频与端到端兼容 | 检查 TTS 长度适配、播放记录、取消重录、CLI 和应用适配 | 保持交付文本一致性、已播放内容不可变、旧任务不会污染新回合；四种 speech_mode 可运行 |
| P7 收尾与性能核对 | 删除重复实现，保留兼容转发，更新配置说明与架构文档 | 离线契约与集成测试通过；确认优化开关和调用次数；需要在线测量时使用已获授权的预算防护 |

依赖顺序为 P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7。P1 不顺带改策略；P2 不顺带改提示质量目标；P4 不取消现有首段及正文机制。每阶段形成可单独审查的改动，失败可回退该阶段，不影响之前通过的阶段。

## 验证矩阵

- **接口兼容**：原参数和返回类型；实例及子类扩展；无 streaming 时原行为；兼容导入路径。
- **提示与材料**：三个阶段、正反双方、普通与渐进任务；完整和部分历史；树与检索开关；证据来源；单一输出格式。
- **反馈模式**：full 与 compact 使用相同有效材料和评价维度；无问题、多问题和格式失败；按回合隔离观众状态。
- **正文更新**：新细节、撤回、ASR 更正、条件变化、首段替换；保留有效论证并移除失效论证；已发布部分不变。
- **交接复用**：历史、证据、草稿或模型选项变化；只有无关派生信息变化；提前任务完成、未完成、失败和迟到。
- **证据修订**：No changes 且长度合适时仍消费选中的补充证据；closing 保留原不新增证据政策；提交仅一次。
- **预算与音频**：默认和自定义阶段时长；单词、音节、音素草稿计量；首段实际音频扣除；预合成复用与失效。
- **故障处理**：模型失败、观众反馈失败、TTS 失败、输入取消或重录；准确记录已经发生的请求和已经播放的内容。

优先扩展现有 `test_debate_prompt_reuse`、`test_authoring_history`、`test_body_feedback`、`test_body_task`、`test_listening_retrieval`、`test_listening_evidence_reuse`、`test_final_input_overlap`、`test_listening_body_cadence`、`test_speech_interfaces` 和应用适配器测试。使用断言检查模型边界收到的实际消息、调用顺序和状态，而不只检查模板含有某个字符串。

离线测试可以证明调用与复用、材料完整性和并发顺序，不能证明真实模型下质量或延迟不退化。在线核对记录首段可播放延迟、首段至正文间隔、反馈及修订耗时、请求数、输入输出 token、推测废弃成本和实际语义质量。比较时固定模型、输入、配置与预算；不预先承诺未经测量的加速比例。

## 完成标准

- 同一项 TreeDebater 辩论能力只有一份权威实现，普通和 streaming 路径都能使用。
- 原接口、配置和扩展入口可用，提速不再隐式关闭检索或替换论点选择。
- 首段优先、正文持续补写修复、紧凑反馈、提前修订、音频复用全部保留。
- 通用提示规则和材料共用，任务范围与输出格式明确选择；没有互相冲突的结构要求。
- 后台任务不污染正式状态，缓存不会复用过期的有效输入，真实请求准确计费。
- 必要的离线契约、并发与应用集成测试通过；在线性能和质量结论仅在实际验证后记录。
